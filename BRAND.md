# AERION Brand Operating System

## Intent

AERION must feel like a premium endurance control app, not a generic AI dashboard. The product borrows the discipline of Breakaway-like endurance software — dark athletic surfaces, huge clear type, sparse rhythm, phone/app proof confidence, one controlled accent — and translates it into AERION's colder race-control language.

## Translation rule

Do **not** clone Breakaway. Use the underlying design behavior:

- one dominant answer per screen,
- high-contrast dark navy surface,
- large condensed athletic display type,
- sparse modular composition,
- route/progress motif instead of generic icons everywhere,
- restrained accent color,
- very few competing visual weights,
- app-like proof panels, not SaaS card soup.

AERION's version is colder, more technical, and more operational.

## Palette

- Void: `#050914`
- Base navy: `#081125`
- Ink panel: `#10203D`
- Raised panel: `#172A4F`
- Primary text: `#F5F7FB`
- Secondary text: `#D7DEEC`
- Muted text: `#9FB0C9`
- Action accent: `#FF4F8B`
- Telemetry accent: `#7DD3FC`
- Clear: `#55D997`
- Hold: `#FFCF72`
- Extend: `#FF5F7E`

Use coral/pink as the product action signature. Use cyan as instrumentation. Do not flood panels with either.

## Typography

Display:

- condensed athletic/editorial stack,
- uppercase for major screen statements,
- very tight line-height,
- large enough to be the visual object.

Body:

- SF/system stack,
- calm, small, readable,
- never marketing-fluffy.

Numeric:

- mono stack for readiness/control values,
- gives instrumentation confidence.

Labels:

- tiny uppercase,
- wide tracked,
- lighter than old AI-dashboard labels.

## Layout language

### Command Panel

The first object on a screen should feel designed, not assembled. Use command panels for primary status and recommendation.

Rules:

- one dominant sentence/value,
- one supporting explanation,
- one route/progress visual,
- one side evidence/status panel when useful.

### Metric Tile

Metric tiles replace generic KPI cards.

Rules:

- label is small/wide,
- value is condensed/large,
- detail is quiet,
- tone is border/accent only,
- no equal-weight rainbow cards.

### Route Rail

Route rail is the AERION motif: current state → pressure point → next action. Use it for Home, History, Performance, race readiness, and planning.

Rules:

- thin coral/cyan line,
- small nodes,
- optional labels below,
- decorative but tied to app logic.

### Evidence Strip

Evidence strip explains why AERION thinks what it thinks.

Rules:

- three to four evidence items max,
- no debug language,
- show source/meaning/action,
- compact enough to scan.

## Screen rules

### Home

Home must show the entire app state in one instance:

- train today,
- race pressure,
- recovery risk,
- history/load signal,
- goal/readiness limiter,
- safe next action.

Home should not look like six SaaS stats pasted under a hero.

### History

History is a control log, not a database table.

- agenda/log left,
- charts right,
- route-key motif above,
- training status as a status plate,
- activity/health split controls as low-profile switches.

### Performance

Performance should feel like telemetry proof, not spreadsheet analytics.

- fewer chart panels visible at once,
- stronger chart titles,
- evidence strip above chart grid,
- quiet axes/grid,
- accent hierarchy consistent with palette.

## Don'ts

- no generic SaaS glassmorphism,
- no muddy radial glow,
- no random gradients per card,
- no equal visual weight everywhere,
- no heavy all-bold labels,
- no fake consumer fitness cheerleading,
- no decorative colors that do not encode state or action.
